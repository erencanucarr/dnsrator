1) "webRequest" JUSTIFICATION
DNSRator shows the REAL server IP of the visited site. Behind a CDN/proxy (e.g. Cloudflare), the DNS A record and the actual connected server differ, and our users need both. The only Chrome API exposing the true connection IP is chrome.webRequest.onCompleted (details.ip). We use a read-only main_frame listener; we never block, redirect, or modify requests. The IP feeds the toolbar badge (last octet/mnemonic), the on-page hover overlay, and a local per-host cache. No bodies, cookies, headers, or page content are read or transmitted. Core to the extension's single purpose; not replaceable by activeTab.

2) "scripting" JUSTIFICATION
The hover overlay (content/hover-box.js) auto-injects on page load, but tabs already open during install/update/reload, or when the user enables the overlay in Settings, would never receive it without a manual refresh. chrome.scripting.executeScript injects only our own bundled file into open http/https tabs at install, startup, and when the overlay is enabled — so it appears immediately. No remote code is ever injected; no DOM is read or exfiltrated. The script only renders the small user-positioned IP badge.
